# Standalone survey (2026-11-10)

What still ties the hooked ports to `tp.exe`, measured on main 31f64bd6. It sizes plan step 4 (`tpw.exe` without the original exe). The figures come from a one-off scan of `src/game` (comments and strings removed) and of the exe's sections.

## The exe

- Fixed base `0x400000`, **no relocations**. Entry `0x67ee10` (C runtime startup).
- Sections: `.text` 2,967 KB, `cseg` 86 KB (code), `.rdata` 167 KB, `.data` 375 KB on disk and 8,759 KB in memory (mostly `.bss`), plus six small data sections (`dseg`, `uva_data`, `idct_dat`, `grpoly_d`, `tqia_dat`, `lbmpeg_d`, 33 KB in all).
- Imports: 367 functions from 20 DLLs. Most come from KERNEL32 (125), USER32 (38), QMIXER (27), WINMM (15), IMM32 (13) and GDI32 (12). The eight `wea*.dll` files are EA Online (128 functions; their interfaces use MSVC 6 `std::basic_string`). DSOUND and DINPUT have one import each, and DDRAW has two.

| `.rdata` (vtables, constants, tables) | 2,612 | 1,363 | 385 | The same |
| Small data sections | 204 | 105 | about 15 | The same |

## Code pointers stored in the exe's data

| Where | Points to | Slots | Targets |
|---|---|---:|---:|
| `.rdata` | Hooked functions (vtables, mostly) | 3,173 | 1,571 |
| `.data` | Hooked functions | 1,050 | 196 |
| `.data` | Static initialisers (the CRT's init table) | 7,065 | 7,034 |
| `.rdata` | EH funclets (FuncInfo tables) | 3,687 | 3,673 |
| both | C library range | 119 | 102 |
| `.rdata` | Adjustor thunks and thunks | 39 | 39 |

- Each slot that points at a hooked function must be rewritten to point at its port. That is a load-time table: address to port, from `hooks.cpp`.
- The EH tables serve only the original code. A standalone build does not need them.

## Code that runs but has no port

The 100% figure covers the counted code only. Three more kinds of code run in the original:

| Code | Size | Notes |
|---|---:|---|
| Static initialisers | 7,034 functions, 224 KB | Compiler-generated: construct a global, then `atexit` its destructor. 6,655 call only hooked functions and `atexit`; the other 379 only store values. They can be generated by a tool. |
| `cseg` | 86 KB | Hand-written assembly: the RLE sprite blitter (`0x6e73c0`), the software rasteriser's span routines (tables at `0x6f19f0`–`0x6f1a20`), and others. `.text` names 5 entry points directly; more are reached through tables. It is not in `_re/text.asm` and not in the count. |
| C library | 0x679000–0x6b0000 | Out of scope: a modern CRT replaces it. Parity points: heap behaviour, `rand`, float formatting, the x87 control word. |

## Options for the data (the user decides)

- **(a) Keep the original layout.** `tpw.exe` links at another base. At startup it reserves `0x400000`–`0xfc5200`, copies the data sections from the user's own `tp.exe`, then rewrites the code pointers in them to ports. The 16,000 address uses in the ports work unchanged.
- **(b) Real globals.** About 5,500 data addresses become named variables and objects, and the vtables become C++ classes. This is the end state, but a large rewrite before the first run.

`cseg` needs either a port (assembly to C++, benched as before) or removal with the software renderer in Phase 5.
